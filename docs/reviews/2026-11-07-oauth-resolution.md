# OAuth review resolution

Follow-up to `2026-11-07-oauth-review.md`; local changes only, no deployment, live authorization, token issuance or account writes.

1. **Reduced grants:** `src/api/permissions.ts` awaits the SDK’s asynchronous `getTokenInfo()` and requires the four requested canonical scope tokens before initialization returns an authorized session and before every authenticated post. Ordering and extra scopes are accepted. Unknown combined/wildcard equivalents fail closed rather than broadening the request. Missing permissions produce fixed actionable text and cannot reach the write fetch handler. Tests first reproduced an `atproto`-only restored session entering the workflow, then verify rejection, no write, reordered scopes and a later reduced grant.
2. **Logout:** the UI always describes local signout and directs users to connected-app settings. It never treats resolved SDK signOut as provider-revocation confirmation. Exposed exceptions retain an additional warning. SDK credential ownership is unchanged; no custom revocation request is added. A hook regression covers ordinary resolved signout and independent relogin without resurrecting cached initialization state.
3. **Bounded profile lookup:** optional public profile resolution uses a ten-second abort signal; failures return the authorized DID as display identity. Public transport accepts an optional backwards-compatible signal. Tests cover the timeout configuration, fallback and signal forwarding.

Verification after fixes and formatting: `npm test` passed 153 tests across 21 files; `npm run lint`, `npm run build`, five synthetic Chromium checks, scoped read-only Prettier checks and `git diff --check` passed. No live token exchange, refresh or revocation acceptance is claimed. Production audit was rerun and still reports 15 high findings. The production Zod audit release blocker remains unresolved. Real authorization/refresh/revocation/PDS-write acceptance still requires separately authorized metadata deployment and disposable-account checks. Scope checking is conservative canonical-token compatibility, not a complete permission-language parser.
